## 三、为什么用 Git LFS

媒体是二进制，git 不做增量压缩——同一个成片改一版，plain git 会完整再存一份。
按 Ep1 33 镜 + 全季 188 镜 + 重做变体估算约 **3.8GB**，plain git 会撑爆 GitHub 的 1GB 软限制、
最终触发 5GB 硬限制把仓库锁死。LFS 只存指针，本体单独存储，改版只占新增部分。

LFS 免费额度：1GB 存储 + 1GB/月 流量。当前占用约 173MB，还有余量。

## 四、⚠️ 三个必须知道的坑

### 坑一：`git status` 会永久挂死

它会全量扫描工作树，遇到 iCloud 占位符（dataless）就卡在 `read()` 上。
实测在 6.9GB 媒体目录上跑 3 分半没返回。

**用这些代替**：
```bash
git --git-dir=~/.minimax/git-repos/xiaoliuer diff-index --name-status HEAD   # 比对
git --git-dir=~/.minimax/git-repos/xiaoliuer ls-tree -r -z --name-only HEAD  # 跟踪清单
```

### 坑二：`git add -A` 会被「已跟踪的 dataless 文件」卡死

目录被 `.gitignore` 排除没关系，但只要某个**已跟踪**的文件是占位符，
git 就必须读它来比对内容 → 永久阻塞，还会留下 `index.lock`。

**处置**（不动磁盘、不读内容）：
```bash
git --git-dir=~/.minimax/git-repos/xiaoliuer update-index --force-remove '<路径>'
```
如果 `index.lock` 报错，说明有 git 进程被强杀过，删掉即可。

### 坑三：`git diff-index` 把 stat 变化误报成「M 已修改」

它是管道命令，只比对 stat 不做内容比对。**iCloud 改写文件**（卸载/重写）会改变 mtime，
于是 79 个文件全报 M，但逐个哈希核对后内容其实完全一致。

**要真实差异，用 `tools/safe_commit_push.py`** —— 它直接算 blob 哈希跟 HEAD 比。

## 五、日常提交

**别手动敲 `git add -A && git commit && git push`**，用这个：

```bash
python3 tools/safe_commit_push.py --dry-run          # 先体检
python3 tools/safe_commit_push.py -m "提交信息"        # 体检通过才提交并推送
python3 tools/safe_commit_push.py -m "..." --skip-push  # 只提交不推送
```

它会依次做：扫描已跟踪文件里的 dataless（挡住挂死）→ 算真实差异 → add → commit → push，
每一步都有明确的失败原因，不会像裸 git 那样「卡住但不知道卡在哪」。

## 六、Git LFS 的 PATH 问题

LFS filter 已配成**绝对路径**，所以 `git add`/`push`/`clone` 都能工作：

```
filter.lfs.clean    /Users/guojiayuan/XiaoliuerVideoGen/bin/git-lfs clean -- %f
filter.lfs.smudge   /Users/guojiayuan/XiaoliuerVideoGen/bin/git-lfs smudge -- %f
filter.lfs.process  /Users/guojiayuan/XiaoliuerVideoGen/bin/git-lfs filter-process
```

但 `git lfs` 这个**子命令**本身仍需 git-lfs 在 PATH 上。已写入 `~/.zshrc` / `~/.bash_profile` / `~/.bashrc`：

```bash
export PATH="/Users/guojiayuan/XiaoliuerVideoGen/bin:$PATH"
```

新开终端后 `git lfs version` 可用。已开的终端需要 `source ~/.zshrc`。
桌面应用（MCode）启动的 git 不读 shell 配置，但它靠绝对路径的 filter，一样能用。

## 七、iCloud 驱逐守护与 pin

本机跑着一个自建守护 `~/.icloud_evict_daemon.py`，会把 iCloud 文件卸载成本地占位符以腾磁盘。
它认一份保护名单 `~/.icloud_pins`（每行一条相对 iCloud 根的路径），重叠的路径一律不驱逐。

**当前已把整个项目加入 pin**：
```
本机迁移/Movies/Xiaoliuer
```

这样既避免了「读一半被驱逐」的活锁，也等于替你做了 Finder「保留下载」那一步。
代价：项目里的原片最多占 7.4GB 本地空间（当前可用 107GiB，放得下）。

守护日志里会看到：`pin 生效：跳过 1 个目标（本机迁移/Movies/Xiaoliuer）`。
