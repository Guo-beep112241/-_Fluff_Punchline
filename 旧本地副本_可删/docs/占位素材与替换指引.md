## 二、为什么选这两张

判断标准只有一个：**脸部结构清晰度**。因为整个项目最大的风险是「换脸」——生出来像只萨摩耶，但不像小六二。

| 定妆图 | 优点 | 代价 |
|---|---|---|
| 成年 | 完全正面、左右对称、眼睛睁开、鼻头和毛发锐度极高、无项圈无道具 | 只有头部，没有全身 |
| 幼犬 | 正面、鼻子眼睛细节锐利、耳朵低垂（符合 3 个月龄）、绿色虚化背景不抢主体 | 嘴部略被毛遮挡 |

**被淘汰的典型原因**（供你选真实照片时对照）：

- 粉色背景那张——脸部最清晰，但**项圈**是配饰、**粉色地面**会带偏肤色
- 黄花田那张幼犬——全身正面很标准，但**黄色背景**给白毛加暖色偏色
- 藤椅那张幼犬——耳朵形态最像 3 个月龄（软塌），但**蓝天背景**偏色、**藤椅**是道具
- 纯侧脸那张——毛质最漂亮，但**侧脸做不了身份参考**，模型学不到脸型结构

## 三、怎么改成小六二（两条路径）

### 路径 A：定妆图 —— 图生图（推荐）

H3 的图像生成支持 `input_urls`（图生图）。流程：

1. 把小六二的照片放进 `10_工作素材/characters/_incoming/`
2. 质检 Agent 挑出**定版照**，存为 `x6_adult_face_01.jpg` / `x6_puppy_face_01.jpg`
3. **直接替换** `10_工作素材/characters/` 下的同名文件

**替换即生效。** 因为提示词里写的是 `<Picture 1>` 而不是文件名——`<Picture 1>` 指向的是「上传顺序第 1 个」，换成小六二后，提示词一个字都不用改。

> ⚠️ 图像生成服务在本次制作时点返回 500（服务端故障，非请求问题）。恢复后可用 `generate_image` 的 `input_urls` 做「以小六二照片为底、保留构图」的精修，但**不是必需的**——直接用小六二原片做参考更真实。

### 路径 B：定妆视频 —— 视频编辑

H3 支持 instruction-based editing。把占位视频和真实照片一起喂进去，让模型把狗换成小六二：

```
reference_videos: [占位定妆视频]   ← 被编辑的源
reference_images: [小六二定妆照]   ← 身份来源
prompt: 把 <Video 1> 里的狗替换成 <Subject 1>（小六二），保持动作、镜头运动、
        背景、光线和音轨不变
```

**关键**：必须写明「保持动作、镜头运动、背景、光线不变」。这是视频编辑任务，不是重新生成。

如果这条路效果不好，退回更稳的做法：**用小六二的定妆图重新生成一遍行为镜头**（等价于阶段 4 单镜头验证，只是把参考图换成小六二的）。占位视频本来就不是最终资产，它只是用来验证「这个动作能不能生成出来」。

## 四、占位素材什么时候被替换

| 阶段 | 占位素材的作用 | 替换时机 |
|---|---|---|
| 阶段 0 素材入库 | 无 | — |
| 阶段 1 圣经 | 写出**占位**萨摩耶的特征词，验证提示词模板能跑 | 真实照片到位后重写为小六二的特征词 |
| 阶段 2–3 剧本分镜 | 验证起承转合和笑点结构 | 剧本本身不用改，只需把「幼犬/成年」对应到真实时间线 |
| **阶段 4 单镜头验证** | **验证生成链路本身**（时长、比例、提示词格式、音轨） | **换小六二定妆图后重跑这一镜** |
| 阶段 5 批量生成 | 无 | 全程用小六二定妆图 |
| 阶段 6 剪辑 | 无 | — |

**关键点：阶段 4 必须用小六二的定妆图重跑一次。** 占位镜头通过 ≠ 小六二通过。链路验证和形象验证是两件事。
