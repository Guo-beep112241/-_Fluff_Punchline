## 一、这是什么

给家里的萨摩耶「小六二」做**搞笑 AI 短视频短剧**，发抖音/小红书/视频号。

- **模型**：MiniMax H3（`MiniMax-H3`）
- **画幅**：竖屏 9:16
- **角色身份**：小六二 1 岁半 = 人类 20 岁 = **大学生**，**专业相声**，还在努力学、经常搞砸
- **形态**：画面里**始终是萨摩耶狗**（建模不变），但**它会说人话**——这是主线核心，第一人称自述
- **主线**：从「一个人分演两角」走到「正式站上一次台」
- **场景**：**大学校园**（宿舍、食堂、排练室、教室、图书馆、快递驿站、小剧场）
- **单集**：**3 分钟左右**（约 30–36 镜）
- **季名**：S1《还没出师》，8 集（建议先做 Ep1 试播，再做满 Ep1–6）

**核心判断**：这个项目的成败**不取决于剧本创意，而取决于跨镜头的小六二形象一致性**。所有流程设计都围绕这一点。

**权威设定顺序**：`bible/series.md`（世界观）→ `docs/season_plan.md`（季纲）→ `bible/characters.md`（外形）→ 本手册 → `docs/制作方案.md`（技术地基）。
前两者是 2026-10-23 重做后新建的，**优先级高于旧文档**。

## 二、四条铁律

违反任何一条都会毁掉项目。

1. **原片只读，永不修改。** 原片是唯一找不回的东西。所有压缩/裁剪/转码只作用在副本上（`10_工作素材/`）。
2. **文件名必须自我表意。** `253_1734673898.mp4` 这种名字在 AI 流程里是灾难——提示词写「使用 `<Picture 1>`」时你不知道 Picture 1 是哪张狗。
3. **一张参考图只给一个职责。** 形象归形象、场景归场景、动作归动作、运镜归运镜。绝不要求一张图管所有。喂矛盾的多张图，模型会在它们之间摇摆，产出谁都不像的「平均脸」。
4. **每镜一个动作、一个主运镜，时长 4–6 秒。** 超过就拆镜。塞两个动作必失控。

## 三、H3 硬约束（踩过就回不来）

| 项 | 限制 |
|---|---|
| 时长 | **4–15 秒整数秒**，不能 3.5 秒 |
| 分辨率 | 768P 或 2K |
| 单次任务 | **= 一个镜头**。不存在「一次生成一集」 |
| 参考图 | ≤9 张，单个 ≤30 MB，宽高各 256–5760 px |
| 参考视频 | ≤3 段，单段 2–15 秒，**总 ≤15 秒**，≤50 MB |
| 参考音频 | ≤3 段，总 ≤15 秒，且**不能单独使用** |
| 混合总数 | ≤12 个文件 |
| 提示词 | ≤7000 字符 |
| 生成耗时 | 15–30 分钟 |

**两个必须记住的**
- H3 **Max 不支持多模态参考**（只能首/尾帧），本项目必须用 H3.0
- 首尾帧模式与参考素材模式**互斥**，不能混用

你只跟**小六二制片人**说话，它负责派活。五个 Agent 的写入范围互不重叠，可安全并行。

| Agent | 名称 | 产出 |

## 七、下一步该做什么

### 你（用户）要做的

**1. 拍板第一集方向**（最优先）：季纲第二节给了 A / B / C 三个候选方案，各有不同开篇钩子和主打笑点。

**2. 补拍成犬完整背面全身轮廓**（可选，不急）：
新拍的背面照是低头姿态，看不到头，缺完整背面轮廓。手机放低、让狗抬头、背对镜头、站直别动。

**3. iCloud 根治**（一次性）：
Finder 里右键 `~/Movies/Xiaoliuer` →「保留下载 / Keep Downloaded」，把项目钉在本地。
iCloud 持续卸载本地副本会导致 git 操作挂起、文件读取阻塞。

**4. 拍大学场景参考图**（等季纲定稿后）：
真实的宿舍楼、教室、食堂、排练室、公告栏——**你自己拍的实景照**，
AI 需要学这些空间长什么样。没有参考图时 H3 会编造不属于你学校的样子。
用**隔空投送**传到 `10_工作素材/scenes/_incoming/`，**不要提前改名/裁剪/压缩**。

### 我（AI）要做的

1. 用户拍板后 → 派编剧出 `episodes/ep01/script.md` + `storyboard.md`（约 30–36 镜）
2. 派提示词工程师出每镜提示词
3. **阶段 4 单镜头验证**：先只做 3 个镜头验证「狗说中文」的口型（正面 / 侧脸 / 叼东西各一个），
   再验证 1 个正式镜头的形象 —— 这 3 个镜头决定全季怎么拍，**必须在批量生成前做**
4. 768P 试错 → 2K 定稿 → 剪辑发布

## 八、工作流与省钱策略

```
阶段 0 素材入库 → 1 圣经 → 2 剧本 → 3 分镜 → 4 单镜头验证⭐ → 5 批量生成 → 6 剪辑发布
```

**阶段 4 是风险闸门。** 跳过它直接批量生成是最容易犯的错。

**两级生成**（省钱核心）：
```
第一轮  768P + 提示词 → 每镜 2–3 个变体 → 挑最好的构图
第二轮  同一提示词出 2K → 只改一个变量微调
```

**返工预期 2–3 倍是正常的**，预算要留余量。

**一次只改一个变量**——形象不对改参考图，动作不对改动作描述，运镜不对改运镜词。同时改三处就无法归因。

## 九、笑点原则

**主线由小六二自己说人话**（第一人称自述）。它 1 岁半 = 人类 20 岁 = 大学生，专业相声。

笑点优先从**「相声专业要求 vs 狗的身体限制」**的错位里长出来：

| 相声要求 | 狗的现实 | 笑点 |
|---|---|---|
| 手眼身法步 | 四条腿做不了手势 | 亮相只能摇尾巴 |
| 偷气换气 | 犬类腹式呼吸 | 偷不到气，只能偷着喘 |
| 贯口吐字清楚 | 犬类口腔结构 | 念《报菜名》念到一半缺氧趴下 |
| 站稳不动 | 腿外八、蹲不下去、不能久站 | 站久了屁股一沉 |

也可以来自**大学现实**的具体荒诞：查寝、点外卖、微信群、抢选修课、期末周、社团招新、导师谈话、排练室。

**不要**让狗做复杂的人类手势（比划、握手、举道具）——H3 会做崩。真实犬类动作（趴、歪头、炸毛、叼东西）是安全的。

**人类角色默认弱出镜**：声音、画外音、手部特写、背影。绕开真人肖像一致性风险和隐私问题。

**技术红线**：犬类口型与中文不匹配，**台词镜头的口型难度必须标注**（高/低），
优先设计侧脸、背对、低头、嘴部被遮挡的镜头。详见 `bible/series.md` §8。
